    Create GAMBIT Database¶

    The CREATE_GAMBIT_DB module is the final step in the pipeline, assembling all processed data into a functional GAMBIT database.

    Overview¶

    This module takes curated genome metadata, species taxonomy, and k-mer signatures to create two essential output files:

    • database.gdb: GAMBIT database file containing genome metadata and taxonomy
    • database.gs: GAMBIT signatures file with k-mer signatures for all genomes

    Module Details¶

    • Process Name: CREATE_GAMBIT_DB
    • Container: gambitdb-dev-gambitv101
    • Resource Label: process_medium

    Inputs¶

    The module requires three main inputs:

    1. Genome Assembly Metadata¶

    CSV file containing curated information about each genome in the database:

    • Genome accession IDs
    • Assembly metadata
    • Quality metrics
    • Taxonomic assignments

    2. Species Taxon File¶

    CSV file with species and genus-level taxonomy:

    • Species names
    • Taxonomic hierarchy
    • NCBI/GTDB taxonomy mappings

    Created by the ADD_GENUS_ROWS module to include genus-level entries.

    3. Signatures File¶

    K-mer signatures and distnace matrix for all genomes, generated by GAMBIT_DISTS_COMBINED.

    Outputs¶

    database.gdb¶

    The main GAMBIT database file containing:

    • Genome identifiers and metadata
    • Taxonomic assignments
    • Database version and metadata

    database.gs¶

    Companion signatures file containing:

    • K-mer signature array for each genome
    • Linked to database entries by genome ID

    versions.yml¶

    Software versions used in database creation.

    Configuration Parameters¶

    The module accepts several parameters for database metadata:

    --db_key¶

    • Type: String
    • Default: "organisation/database"
    • Description: Unique identifier for the database

    Example: 

    --db_key "theiagen/gambitdb-gtdb-r220"

    --db_version¶

    • Type: String
    • Default: "1.0.0"
    • Description: Version number for the database release

    Example: 

    --db_version "2.1.0"

    --db_author¶

    • Type: String
    • Default: "Theiagen Genomics"
    • Description: Creator or maintainer of the database

    Example: 

    --db_author "Your Organization"

    --db_date¶

    • Type: Date (YYYY-MM-DD)
    • Default: Current date
    • Description: Database creation date

    Example: 

    --db_date "2024-12-01"

    How It Works¶

    The CREATE_GAMBIT_DB module uses the gambitdb-create command:

    1. Validate Inputs: Ensures all required files are present and properly formatted
    2. Process Metadata: Reads and validates genome assembly metadata
    3. Process Taxonomy: Reads species and genus taxonomy information
    4. Load Signatures: Imports k-mer signatures for all genomes
    5. Create Database: Assembles all components into .gdb file
    6. Link Signatures: Creates .gs file linked to database entries
    7. Add Metadata: Embeds database version, author, and date information

    Usage Example¶

    While this module is typically run as part of the full pipeline, you can understand its parameters:

    nextflow run main.nf \
  --input gtdb_metadata.tsv \
  --outdir results \
  --db_key "myorg/bacterial-db" \
  --db_version "1.0.0" \
  --db_author "My Organization" \
  --db_date "2024-12-01" \
  -profile docker

    Output Location¶

    The final database files are saved to: 

    <outdir>/<release-tag>/create_gambit_db/
├── database.gdb
└── database.gs

    Where <release-tag> is set by the --release_tag parameter (default: gtdb-dev).

    Using the Database¶

    Once created, use the database with GAMBIT for bacterial identification:

    # Basic GAMBIT usage
gambit query \
  --db results/gtdb-dev/create_gambit_db/database.gdb \
  --sigfile results/gtdb-dev/create_gambit_db/database.gs \
  --output gambit_query.csv \
  query_genome.fasta

    Best Practices¶

    Database Versioning¶

    Use semantic versioning for database releases: - Major version: Incompatible changes (different GTDB release) - Minor version: Backward-compatible additions (new species) - Patch version: Bug fixes (corrected metadata)

    Database Key Naming¶

    Follow a consistent naming convention: 

    organization/database-source-version

    Examples: - theiagen/gambitdb-gtdb-r220 - mylab/custom-pathogens-v1 - public/clinically-relevant-bacteria

    Metadata Documentation¶

    Document your database by recording: - Source data (GTDB version, download date) - Quality thresholds used - Downsampling parameters - Number of genomes and species - Creation date and author

    Quality Assurance¶

    The CREATE_GAMBIT_DB module includes validation:

    • Metadata integrity: All genomes have complete metadata
    • Signature linking: Every genome has a corresponding signature
    • Taxonomy consistency: No missing or malformed taxonomy entries
    • File format: Outputs conform to GAMBIT database specifications

    Technical Details¶

    Container Image¶

    us-docker.pkg.dev/general-theiagen/theiagen/gambitdb/gambitdb-dev-gambitv101

    Resource Requirements¶

    • CPU: 2-4 cores
    • Memory: 4-8 GB
    • Disk: Minimal (outputs are compressed)
    • Time: 1-5 minutes (depending on database size)

    File Formats¶

    Input Formats: - Genome metadata: CSV - Species taxonomy: CSV - Signatures: GAMBIT .gs format

    Output Formats: - Database: GAMBIT .gdb format (SQLite-based) - Signatures: GAMBIT .gs format (binary)
